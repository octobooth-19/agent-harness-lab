# Agent concepts

**Snapshot and source retrieval date:** 2026-11-18; **last synthesis review:** 2026-11-18.
**Evidence status:** Cross-provider glossary synthesized from reviewed sources. These are working distinctions, not claims that providers use identical terminology.

## Core concepts

| Concept | Working definition | Design implication |
|---|---|---|
| **Model** | The model that interprets context and produces text or structured/tool requests. | Select and evaluate it for a representative workload; do not attribute harness behavior to the model alone. |
| **Agent** | A model operating within instructions, tools, state, and an execution loop to pursue a goal. | Describe the complete runtime and authority, not just the model name. |
| **Harness** | The surrounding runtime: loop, context preparation, tools, environment, state, permissions, observability, and recovery. | Make these parts explicit and test their interactions. |
| **Agent loop** | Repeated model invocation, tool execution, result incorporation, and continuation until completion, handoff, or stop. | Define stop conditions, errors, retries, cancellation, and durable progress. |
| **Tool** | A capability exposed to the model through a structured interface; execution may belong to the client or a hosted service. | Bound inputs and authority; validate outputs and failures at the execution boundary. |
| **Instruction** | Persistent or task-scoped natural-language guidance interpreted by the model. | Useful for behavior, but not a deterministic security control. |
| **Skill** | A discoverable, task-specific procedure, often with supporting references or scripts. | Use progressive disclosure; a skill does not itself grant tool access. |
| **Memory** | Selected information retained beyond the active context, often with a scope. | Record provenance and freshness; distinguish recall from source-of-truth state. |
| **Context** | The active instructions, messages, tool descriptions/results, retrieved evidence, and other data available to a model call. | Optimize for relevant signal and explicitly manage state loss. |
| **Permission / policy** | A runtime or platform rule governing which actions or resources are allowed or require review. | Enforce at the tool/environment boundary; do not rely on prompt compliance. |
| **Evaluation** | A repeatable task/trial plus graders and evidence used to measure a model-and-harness outcome. | Check environment state and process constraints, not only the final answer. |
| **Handoff / delegation** | Transfer of work to another agent or process, or use of a specialist while a manager retains control. | Specify the assignment, output contract, dependencies, and integration review. |

## Useful distinctions

- **Workflow vs agent:** A workflow can prescribe a largely fixed sequence; an agent chooses some steps dynamically. Use the simplest control flow that meets the task.
- **Instruction vs enforcement:** Natural-language instructions steer the model. Sandboxes, permissions, hooks, validators, and CI can impose runtime checks. They are complementary, not interchangeable.
- **Context vs memory vs artifact:** Context is active input; memory is selected retained knowledge; an artifact is explicit durable task output. A transcript or summary should not silently replace the artifact.
- **Outcome vs process evaluation:** A change may pass tests while violating tool, permission, or review constraints. Grade both the resulting state and important process requirements.
- **Product surface vs protocol:** A product can bundle a loop, tools, state, and policy; a model/API protocol may leave those responsibilities to the application. Similar names do not guarantee similar lifecycle semantics.
- **MCP server vs product app server:** An MCP server exposes the MCP tool/resource protocol, whereas a product app server can expose a different integration protocol. OpenAI's current Codex docs say its former `codex mcp-server` was removed and direct integrations to the App Server JSON-RPC protocol, which is marked experimental; this does not remove Codex's ability to connect to external MCP servers.
- **Deferred discovery vs permission:** Tool search controls which definitions enter context and when; it does not grant, deny, or enforce authority. Keep catalog deferral separate from execution permissions and expose only the tools a task needs ([Claude Code SDK tool search](https://code.claude.com/docs/en/agent-sdk/tool-search), partial; [Copilot CLI MCP configuration](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers), partial).
- **Streamed arguments vs validated input:** Fine-grained tool streaming can expose partial JSON before it is complete or validated. Accumulate and validate the full input before parsing or executing the requested action ([Anthropic fine-grained tool streaming](https://platform.claude.com/docs/en/agents-and-tools/tool-use/fine-grained-tool-streaming), partial).
- **Autonomy vs permission:** An agent mode can allow more consecutive steps without user turns while the permission layer still limits available actions. Enabling autonomy is not equivalent to granting broader access or waiving review.
- **Parallel tool requests vs parallel execution:** A model can return several tool requests together, but the client decides safe execution order. Concurrency is appropriate for independent operations; side effects and shared state may require serialization.
- **Session vs environment vs artifact:** A durable agent session can outlive its compute environment; artifacts may be published or retained under separate product rules. Recovery must inspect both orchestration state and the environment's actual files/side effects.
- **Tool protocol vs tool runner:** A tool protocol describes requests and results; an SDK runner may automate the loop, but can constrain where custom approvals, logging, or execution policy fit.
- **Goal vs instruction:** An instruction guides behavior; a goal is a scoped completion contract that states an outcome, verification criteria, and constraints. A goal can persist across a long task without granting unbounded autonomy.
- **Prompt template vs persistent instruction:** A prompt template is explicitly selected for an interaction; an instruction is supplied by the host as standing guidance. The file names and loading rules are product-specific.
- **Scheduled agent vs repository workflow:** A provider automation may be configured and stored outside the repository, while a repository-native workflow can use checked-in declarative files and deterministic policy steps. Verify ownership, trigger, write path, and approval semantics before calling both "automation."

## Provider-specific terminology cautions

- **OpenAI:** Codex, Responses API, Agents SDK, Agents API, Workspace Agents, and Agent Builder expose different ownership of loops, state, environments, and approvals. Local Codex rules and Work Cloud policy are not interchangeable; custom prompts are deprecated in favor of skills. Agent Builder is scheduled to shut down Nov. 30, 2026. In Agents API, sessions and environments have separate lifecycles; reconnects do not replay missed stream events, and environment IDs do not restore files. The former Codex MCP server command is removed; its App Server JSON-RPC integration is experimental and is not the protocol used to connect Codex to external MCP servers. See [Agents guide](https://developers.openai.com/api/docs/guides/agents), [Codex rules](https://learn.chatgpt.com/docs/agent-configuration/rules), [Custom Prompts](https://learn.chatgpt.com/docs/custom-prompts), [Codex MCP server removal](https://learn.chatgpt.com/docs/mcp-server), [Codex Goals](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex), [Environment lifecycle](https://developers.openai.com/api/docs/guides/agents-api/environments/lifecycle), [Sessions](https://developers.openai.com/api/docs/guides/agents-api/sessions), [Workspace Agent triggers](https://developers.openai.com/workspace-agents/trigger-runs), and [Agent Builder](https://developers.openai.com/api/docs/guides/agent-builder).
- **Anthropic:** Claude Code, Agent SDK, Messages API tools, and Managed Agents differ in who executes tools and manages sessions. Managed Agents adds server-side permission policies, budgets, threads, and dynamic workflows that do not apply to the client-managed Messages API loop. Its tool-context and compaction features carry API version/beta conditions; multiple `tool_use` blocks still do not force concurrent execution. See [Agent SDK loop](https://code.claude.com/docs/en/agent-sdk/agent-loop), [tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), [Tool Runner](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-runner), [Managed Agents policies](https://platform.claude.com/docs/en/managed-agents/permission-policies), [Session threads](https://platform.claude.com/docs/en/managed-agents/session-threads), [Workflow runs](https://platform.claude.com/docs/en/managed-agents/workflow-runs), [Manage tool context](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context), [Compaction](https://platform.claude.com/docs/en/build-with-claude/compaction), and [Parallel tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use).
- **GitHub Copilot:** CLI, IDE, app, cloud agent, and dynamic workflows differ in execution and control; SDK loop details should not be generalized to every Copilot surface. Prompt files are invoked templates, while custom instructions are standing context; hooks are runtime mechanisms with host-specific event support. CLI Autopilot continuation, approval, and user-question flags are separate controls. Copilot Automations are configured outside Git, while Agentic Workflows are repository Markdown/YAML compiled to Actions with read-only defaults and safe outputs. See [about Copilot agents](https://docs.github.com/en/copilot/concepts/agent-capabilities/about-agents/about-github-copilot-agents), [prompt files](https://docs.github.com/en/copilot/concepts/prompting-and-context/prompt-files), [hooks](https://docs.github.com/en/copilot/concepts/customizations/hooks), [Autopilot mode](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/use-autopilot-mode), [Copilot Automations](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations), [GitHub Agentic Workflows](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-github-agentic-workflows), [Copilot Dreaming](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-dreaming), and [Tool search](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/tool-search).

## Uncertainty and conflicts

Providers reuse familiar words—agent, skill, context, memory, approval—for different implementations. This glossary is a shared mental model for design discussions, not a replacement for the product-specific docs or a claim that every term has a canonical definition. Historical blog and release claims are time-bound; check current documentation before implementing a provider-specific behavior.

## Further distinctions from the 2026-11-18 review batch

- **Harness vs sandbox:** the runtime may own the loop, approvals, tracing, and run state while a separate sandbox owns filesystem and command execution. Define which boundary applies to credentials, network access, and recovery rather than using “agent environment” as one undifferentiated term ([OpenAI Sandbox Agents](https://developers.openai.com/api/docs/guides/agents/sandboxes), partial; [Anthropic Managed Agents](https://www.anthropic.com/research/managed-agents), full).
- **Tool request vs tool execution:** a model's batch of tool calls does not itself establish safe concurrency. The client decides whether calls can run in parallel, and tools that share mutable state or create side effects may need serialization ([Anthropic parallel tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use), previously reviewed; [Copilot internal analytics agent](https://github.blog/ai-and-ml/github-copilot/how-we-built-an-internal-data-analytics-agent/), partial).
- **Evaluation assertion vs system quality:** a passing assertion checks a condition, not overall quality; results from a controlled loop may not transfer to the production harness. Evaluate representative end-to-end tasks, environment state, and process constraints, not just model output ([OpenAI Promptfoo + Codex](https://developers.openai.com/api/docs/guides/promptfoo-codex), partial; [OpenAI harness-aware plugin evals](https://developers.openai.com/cookbook/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals), partial; [Copilot analytics agent](https://github.blog/ai-and-ml/github-copilot/how-we-built-an-internal-data-analytics-agent/), partial).
- **Autonomy vs authority:** a mode that continues without frequent user turns does not by itself grant broader tool permissions. Keep permission policy, approval, and task continuation independently observable ([Copilot merge-assistance changelog](https://github.blog/changelog/2026-10-28-agent-merge-watches-and-fixes-pull-requests-in-the-cloud), full; [Anthropic auto-mode research](https://www.anthropic.com/research/claude-code-auto-mode), full).
- **Checkpoint vs rollback:** a checkpoint may cover only tool-mediated file edits; it does not necessarily undo shell side effects, user edits, credentials, or remote actions. Pair narrow checkpoints with version control and explicit environment cleanup ([Claude Code autonomy announcement](https://www.anthropic.com/news/enabling-claude-code-to-work-more-autonomously), full).
- **Repository workflow vs hosted automation:** GitHub Agentic Workflows are repository-owned, read-only-by-default Actions inputs with safe outputs; Copilot Automations are shared cloud-agent configurations with different visibility, edit, billing and policy rules. Do not equate their files, permissions, or approval paths ([Agentic Workflows GA](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available), full; [Shared Copilot Automations](https://github.blog/changelog/2026-10-28-build-shared-workflows-for-your-team-with-copilot-automations), full).
- **Permission mode vs sandbox:** assisted permission review is a distinct approval layer; it does not enforce filesystem/network isolation. Prefer scoped permissions and a sandbox, and require human review for sensitive actions ([Copilot safe commands](https://docs.github.com/en/copilot/concepts/customizations/allowing-safe-commands), full).
- **Telemetry vs transcript capture:** trace/metric availability does not imply prompt or tool-content collection. Check capture defaults, admin overrides, and retention before enabling detailed telemetry ([Copilot OpenTelemetry](https://docs.github.com/en/copilot/concepts/enterprise/opentelemetry), full).
- **Product metric vs independent quality measure:** Copilot code-review outcome signals and addressed-rate metrics describe product usage; they do not prove review correctness or causal impact. Treat them as operational indicators and pair them with quality evaluation ([Repository insights release](https://github.blog/changelog/2026-11-17-track-copilot-code-review-outcomes-in-repository-insights), full).
- **Trace vs evaluation:** traces support debugging and may supply candidate examples, but an evaluation still needs representative tasks and explicit grading; do not treat telemetry as a quality score ([OpenAI Agents SDK observability](https://developers.openai.com/api/docs/guides/agents/integrations-observability), partial).
- **Vendor Evals product vs application-owned evaluation:** OpenAI's Evals/Graders references carry a dated read-only/shutdown notice in this snapshot. Preserve independent eval cases and graders in a durable system, and verify vendor product lifecycle before choosing a service endpoint ([OpenAI datasets quickstart](https://developers.openai.com/api/docs/guides/evaluation-getting-started), partial; [Graders](https://developers.openai.com/api/docs/guides/graders), partial).
- **Agent call vs async tool job:** an async tool result is still application-owned work and must be reconciled with its originating call; it is not the same as a provider-hosted background run ([OpenAI async tool calling](https://developers.openai.com/api/docs/guides/async-tool-calling), partial).
- **Client tool vs server tool:** a client tool requires the application to execute and return a matching result; an Anthropic server tool runs on the provider side and may instead pause/continue under its own protocol. Preserve the exact response and ordering contract for the chosen tool type ([Anthropic server tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/server-tools), full; [Tool-using agent tutorial](https://platform.claude.com/docs/en/agents-and-tools/tool-use/build-a-tool-using-agent), partial).
- **Deferred definition vs deferred authority:** OpenAI tool search and GitHub MCP toolsets affect which definitions are discoverable or exposed; neither is a substitute for runtime authorization. Reconcile the model-visible catalog with the executor's actual permission set ([OpenAI tool search](https://developers.openai.com/api/docs/guides/tools-tool-search), partial; [GitHub MCP toolsets](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/customize-copilot/extend-copilot-with-tools-and-context/configure-toolsets), full).
- **Direct call vs programmatic tool call:** OpenAI's programmatic tool calling lets generated code orchestrate tools inside a restricted V8 runtime; it differs from direct model-issued calls and does not provide general filesystem, network, Node, or persistent JS state. Keep approval-sensitive writes on direct calls unless the harness deliberately supplies and verifies another approval mechanism ([Programmatic Tool Calling](https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling), partial).
- **Provider-hosted web tool vs sandbox network:** Anthropic Managed Agents web-domain restrictions govern the hosted search/fetch tools, not arbitrary egress from a self-hosted worker sandbox. Apply and test network policy at the relevant execution boundary ([Managed Agents web restrictions](https://platform.claude.com/docs/en/managed-agents/tools-web-restrictions), partial; [self-hosted worker deployment](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes-workers), partial).
- **MCP tunnel vs ordinary MCP connection:** Anthropic MCP tunnels are a research-preview proxy deployment with their own TLS trust, route matching, certificate, and token lifecycle; do not assume the standard client connection contract or stable availability ([MCP tunnels reference](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/reference), partial).
- **Model picker choice vs orchestrator:** Copilot Fusion is documented as routing one prompt through a single, cascade, or critique pattern and may choose different models per prompt; it is not itself a model or independent context window. Current routing policy and pool are product-specific and change over time ([Copilot Fusion](https://docs.github.com/en/copilot/concepts/models/copilot-fusion), partial).
- **Managed agent loop vs application-owned loop:** Anthropic Managed Agents stores session history and runs built-in sandbox tools server-side, while the Messages API loop requires the application to carry history, execute client tools, and continue the loop. A migration changes state and execution ownership, not only SDK syntax; the Managed Agents migration and Console docs were partial and mark the feature beta ([Migration](https://platform.claude.com/docs/en/managed-agents/migration), partial; [Build in Console](https://platform.claude.com/docs/en/managed-agents/onboarding), partial).
- **Model availability vs model identity:** A Copilot feature may route across multiple eligible models or use utility models outside the picker; plan, client, admin policy, and rollout determine availability. Record the actual model and surface when reproducibility matters, and verify current model lists rather than treating a dated roster as a stable interface ([Copilot model overview](https://docs.github.com/en/copilot/concepts/models/overview), full; [Supported models](https://docs.github.com/en/copilot/reference/ai-models/supported-models), partial).
- **Stop reason vs request failure:** Anthropic Messages API `stop_reason` distinguishes a completed turn from truncation, tool handoff, paused server-tool work, or refusal. Branch on the documented reason and do not infer success from HTTP status alone; event/response handling is API- and tool-specific ([Stop reasons and fallback](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons), partial).
- **Schema validity vs action validity:** Constrained JSON or strict tool schemas can guarantee shape, but they do not prove the proposed data is authorized, factually correct, or safe to execute. Validate domain constraints and permissions at the application boundary ([Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), partial).
- **Policy scope vs execution surface:** Copilot enterprise MCP allowlists do not cover repository custom-agent MCP profiles according to the reviewed page; local sandbox settings, cloud sandboxes, and GitHub Actions runners also use distinct controls. Map each policy to the runtime it actually governs and test effective access ([Copilot MCP allowlist](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-mcp-usage/configure-enterprise-allowlist), partial; [Copilot sandbox settings](https://docs.github.com/en/copilot/how-tos/cloud-and-local-sandboxes/configuring-local-sandbox-settings), partial; [Copilot cloud runner controls](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-organization/configure-runner-for-coding-agent), partial).
- **Structured tool vs computer use:** a structured call exposes a bounded, typed operation; UI-oriented tools act through desktop or browser state, which may include authenticated sites. Do not treat them as equivalent in scope, determinism, or approval requirements ([Copilot computer use](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/computer-use), full; [Copilot browser use](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/browser-use), full; [Anthropic browser-use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool), partial).
- **Metric vs accounting ledger:** A product usage report can help track trends without being a complete record of work or cost. Copilot's dated usage-metrics changelog documents a cap, client/version conditions and possible telemetry undercount; use it as an operational signal, not exact accounting ([Copilot usage-metrics changelog](https://github.blog/changelog/2026-10-22-custom-skills-agents-and-mcp-servers-in-usage-metrics-api), full).
- **Hosted agent vs execution environment:** session state, orchestration, compute, and workspace files can have distinct owners and lifetimes. Check each provider contract and explicitly clean up external compute instead of assuming session deletion ends the environment ([OpenAI AWS Lambda MicroVMs](https://developers.openai.com/api/docs/guides/agents-api/environments/providers/aws), full; [OpenAI Databricks Sandbox](https://developers.openai.com/api/docs/guides/agents-api/environments/providers/databricks), full).
- **Repository indexing vs model training:** retrieval/indexing is a context mechanism, not itself evidence that repository content is used for model training. It can still transmit data to a service: Copilot's reviewed VS Code guidance warns of uploads when indexing non-GitHub repositories, so document and authorize the actual data path ([Indexing repositories for GitHub Copilot](https://docs.github.com/en/copilot/concepts/prompting-and-context/repository-indexing), full).
- **Source read vs moving changelog sample:** reading a top release entry does not establish full product history. The Anthropic Claude Code changelog remains partial in this snapshot; report its visible entry as an observation at access time, not as the complete release history ([Claude Code changelog](https://code.claude.com/docs/en/changelog), partial).
- **Retrieval experiment vs portable benchmark:** contextual retrieval results and coding-assistance study outcomes are source-specific experiments with model, sample, and methodology limitations. Record those conditions and test on the target workload before using the figures to justify a system choice ([Anthropic Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval), full; [AI assistance and coding skills](https://www.anthropic.com/research/AI-assistance-coding-skills), full).
- **Safety evaluation vs single-turn pass rate:** preregister analysis, validate graders against human labels, report uncertainty, and include multi-turn simulations and paired benign/harmful cases. These are recommendations from Anthropic's research article, not a standardized compliance requirement ([Building strong safety evaluations](https://www.anthropic.com/research/building-strong-safety-evaluations), full).
- **MCP tunnel preview vs general deployment guarantee:** apply explicit OAuth, narrow upstream IP/network scope, credential rotation and image pinning where relevant, but verify whether the specific host/server supports the preview architecture and controls ([MCP tunnels security](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/security), full).
- **Realtime function tool vs remote MCP tool:** OpenAI's Realtime API leaves function execution with the application but can call a configured remote MCP server through the API. Choose based on where business logic, approvals, and private-system access must live; these are Realtime-specific semantics ([Realtime with tools](https://developers.openai.com/api/docs/guides/realtime-mcp), partial).
- **Cloud-agent launch vs local tool call:** invoking Copilot cloud agent through GitHub's remote MCP server starts asynchronous work that produces a draft pull request; it is not simply another synchronous tool result. Preserve the PR review path and check that the host supports the remote server ([Using Copilot cloud agent via the GitHub MCP Server](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-with-mcp), full).
- **Background response vs durable workflow:** OpenAI background mode makes one Responses API request asynchronous and retrievable; the application still owns follow-up tool calls, deduplication, terminal failure handling, and task state. Its temporary encrypted retention applies even when ordinary response storage is disabled, so check the current data controls before use ([Background mode](https://developers.openai.com/api/docs/guides/background), partial).
- **Interactive schedule vs unattended automation:** Copilot CLI scheduled prompts depend on an open/resumed session and are experimental; Copilot Automations have separate cloud triggers, tools, credit budgets, and human-approved self-improvement. Do not treat the CLI schedule as a durable repository scheduler or conflate the two permission models ([CLI scheduled prompts](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/schedule-prompts), partial; [Automation controls](https://github.blog/changelog/2026-10-28-new-tools-triggers-and-cost-controls-for-copilot-automations), full; [Automation self-improvement](https://github.blog/changelog/2026-10-28-copilot-automations-now-learn-from-outcomes-and-self-improve), full).
- **Event preview vs committed record:** Anthropic Managed Agents event deltas are provisional display events; the buffered `agent.message` is authoritative. Stream and webhook event names/payloads differ, and a webhook's event ID/type is not the latest session state—fetch the object and reconcile the right protocol ([Event deltas](https://platform.claude.com/docs/en/managed-agents/event-deltas), partial; [Session stream](https://platform.claude.com/docs/en/managed-agents/events-and-streaming), partial; [Webhooks](https://platform.claude.com/docs/en/managed-agents/webhooks), partial).
- **Idle vs complete:** an Anthropic Managed Agent session can be `idle` while a workflow run remains open, so task completion must be tied to the run's completion event/state rather than the session status alone ([Session operations](https://platform.claude.com/docs/en/managed-agents/session-operations), partial).
- **Hosted agent vs self-hosted execution:** in Anthropic self-hosted sandboxes, the model/agent and queue remain provider-managed while tool execution, files, egress, and data retention shift to the operator; separate environment keys, per-session secrets, and filesystem isolation by trust boundary ([Self-hosted sandboxes](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes), partial; [Security model](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes-security), partial).
- **Self-hosted sandbox vs self-hosted service:** moving tool execution to your infrastructure does not move the API, agent loop, or session store. Anthropic documents a separate full self-hosted service deployment with its own database/release/security duties; distinguish which layer owns inference, history, and execution ([Self-hosted sandboxes](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes), partial; [Self-hosted Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/self-hosted), partial).
- **Session vs agent version:** a session may resolve to the latest agent configuration or pin a numbered version; record that version with outputs when staged rollouts or reproducibility matter ([Start a session](https://platform.claude.com/docs/en/managed-agents/sessions), partial).
- **Scheduled deployment vs session timer:** a provider-managed deployment can create recurring sessions on a cron/timezone, while Copilot CLI `/every` runs only in an active/resumed interactive session. These are distinct hosting, state, and permission models; distinguish them from repository CI schedules too ([Anthropic scheduled deployments](https://platform.claude.com/docs/en/managed-agents/scheduled-deployments), partial; [Copilot CLI scheduled prompts](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/schedule-prompts), partial).
- **Usage metric vs outcome evaluation:** feature-use or token counts describe activity and cost, not task correctness. Copilot's chat/agent usage reports count engagement under specific date-window and policy rules; pair operational metrics with artifact/state grading ([Copilot impact dashboard update](https://github.blog/changelog/2026-11-06-copilot-impact-dashboard-adds-chat-and-vs-code-agent-usage), full; [GPT-Live evaluation guide](https://developers.openai.com/cookbook/examples/audio/voice_agent_evaluation), partial).
- **Agent instructions vs workflow artifacts:** Codex reads `AGENTS.md` as optional repository guidance, while goals, plans, prompts, and phase context in its cookbook are team-defined workflow artifacts. None of those file conventions replace runtime permissions or review ([Codex CLI](https://learn.chatgpt.com/docs/codex/cli), partial; [Iterating development workflows](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex), partial).
- **Agent runtime vs execution sandbox:** an Agents SDK host can own orchestration, policy, approvals, credentials, and audit while a separate sandbox runs repository commands and returns patches. Decide explicitly which process receives secrets and make cleanup/verification part of the task lifecycle ([OpenAI sandbox migration](https://developers.openai.com/cookbook/examples/agents_sdk/sandboxed-code-migration/sandboxed_code_migration_agent), partial).
- **Self-hosted service vs local data boundary:** Anthropic's self-hosted Managed Agents controls the server/database/workers, but requests still go to the configured model provider and worker egress depends on operator policy; session deletion does not erase backups, logs, memory stores, or workspace volumes ([Self-hosted data and access](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access), partial).
- **Memory curation vs direct edit:** Anthropic Dreams consumes transcripts and an existing memory store to generate a separate store; its instructions guide synthesis but do not target individual entries. Inspect and promote results through the memory API under the feature's current preview, model, and retention constraints ([Managed Agents Dreams](https://platform.claude.com/docs/en/managed-agents/dreams), partial).
- **Model choice vs model capability contract:** Copilot CLI custom models need tool calling and streaming, and configured token limits must match the model's real context window; organization settings can also inherit enterprise policy. Validate both model/runtime compatibility and effective access before relying on a custom model ([Copilot CLI custom models](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-llm-models), partial; [Organization model availability](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-organization/manage-default-models), partial).
- **Parallel orchestration vs fixed workflow:** OpenAI's beta multi-agent feature lets a root agent delegate independent work and synthesize results, but adds cost and is a poor fit for tightly ordered work or shared mutable state; it is not a deterministic execution graph ([Responses API multi-agent](https://developers.openai.com/api/docs/guides/responses-multi-agent), partial).
- **Evaluation score vs general capability:** LifeVal measures selected everyday-assistant tasks, and Anthropic documents sensitivity to benchmark setup and implementation. Preserve task distributions, model/version, grader, and uncertainty; do not transfer a score to unrelated coding or agent workloads ([LifeVal](https://openai.com/index/lifeval/), partial; [Evaluating AI systems](https://www.anthropic.com/research/evaluating-ai-systems), partial).
- **Local harness vs local data handling:** Copilot's scheduled Local-harness retirement is a VS Code client migration; the replacement can still work on local files, while sandbox, permission, telemetry, and provider-routing controls remain separate decisions ([Local harness transition](https://github.blog/changelog/2026-11-16-vs-code-retires-the-local-harness-in-february-2027), partial; [Local model discovery](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli), full).
- **Observed behavior vs confirmed mechanism:** OpenAI's reporting framework allows early disclosure of anomalies before explanation and notes some may be spurious. Preserve raw traces and confidence separately from causal claims, and update the interpretation as evidence accumulates ([Model misalignment reporting framework](https://openai.com/index/model-misalignment-reporting-framework/), partial).
- **Task workspace vs environment:** Codex Cloud tasks use separate workspaces; an environment provides setup, not a shared working tree. Review each task's output before promoting it into another workspace ([Codex Cloud](https://learn.chatgpt.com/docs/cloud), full).
- **Retrieval vs memory:** A vector-store search returns candidate evidence for a request; it is not inherently a persistent user memory or a trusted instruction channel ([OpenAI Retrieval](https://developers.openai.com/api/docs/guides/retrieval), partial).
- **Session history vs run completion:** In Managed Agents, an idle event can indicate that input is required and a workflow may remain open; webhook notifications may be missed. Check event history, current session state, and workflow status separately ([Monitoring](https://platform.claude.com/docs/en/managed-agents/secure-deployment-monitoring), partial; [Managed Agents reference](https://platform.claude.com/docs/en/managed-agents/reference), partial).
- **Content exclusion vs deletion:** Copilot content exclusion is a feature- and client-dependent use control, while stored session records have their own storage, synchronization, and lifecycle. Do not treat either as a substitute for confirming the other's behavior ([Content exclusion](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion), partial; [Session data](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/session-data), partial).
- **Identity rule vs audience check:** An OpenAI workload identity federation rule applies the configured principal/workspace and identity conditions; an audience-only match is not a complete identity policy ([Federation rules](https://developers.openai.com/api/docs/guides/workload-identity-federation/federation-rules), partial).
- **Voice model vs task backend:** GPT-Live owns spoken conversation while a separately chosen backend reasons and uses tools; application permissions, confirmations, task records, and forwarding policy remain external responsibilities ([GPT-Live overview](https://developers.openai.com/api/docs/guides/live), partial).
- **Session model choice vs global default:** Copilot CLI's selected model is session-scoped and persists on resume; available models are constrained by plan and organization/enterprise policy. Copilot Fusion is a separate automatic-routing choice ([Choosing a model](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/choose-a-model), partial; [Default availability](https://docs.github.com/en/copilot/concepts/enterprise/default-availability), partial).
- **Self-hosting vs state migration:** Anthropic's self-hosted Managed Agents runs its own service but does not import hosted sessions or associated agent resources; recreate the required state and independently configure inference, database, credentials, and sandboxing ([Self-hosted differences](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences), partial).
- **Model capability vs evaluation validity:** Anthropic's timed technical-task case shows that a test can lose discriminative power as models improve. Revalidate task difficulty, model/version, and job relevance rather than treating an old score as a stable measure ([AI-resistant technical evaluations](https://www.anthropic.com/research/AI-resistant-technical-evaluations), partial).
- **Model reasoning vs deterministic retrieval:** The biological-agent case study attributes better dataset construction to a deterministic retrieval layer in that task. Test structured retrieval and validation as part of the harness before assuming a model-only prompt will fix source-data reliability ([Agents in biology](https://www.anthropic.com/research/agents-in-biology), partial).
- **Trace eval vs macro eval:** Score tool calls, handoffs, policy decisions, and outcomes per run, then group repeated findings across a trace population; keep synthetic examples, external graders, and human review explicitly labeled ([OpenAI Trace grading](https://developers.openai.com/api/docs/guides/trace-grading), full; [Macro Evals](https://developers.openai.com/cookbook/examples/partners/macro_evals_for_agentic_systems/macro_evals_for_agentic_systems), partial).
- **Benchmark score vs task validity:** Coding evaluation scores depend on task statements, test correctness/coverage, and contamination. Audit whether success/failure reflects the requested behavior before using benchmark results to make capability claims ([OpenAI coding-evaluation audits](https://openai.com/index/separating-signal-from-noise-coding-evaluations/), partial; [SWE-bench Verified assessment](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified), partial).
- **Governance repo vs access-control boundary:** Copilot `.github-private` centralizes reviewable agent/plugin settings, but settings may apply beyond the repository's own readers; separately decide who can propose changes and who is covered by the policy ([Creating `.github-private`](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/manage-agents/create-github-private-repo), partial).
- **Preserved reasoning vs mutable prompt:** On Anthropic's documented supported models, conversation prefixes and returned thinking blocks have serialization requirements; this is an API replay constraint, not a prompt-based permission guarantee ([Change tools or instructions](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/change-tools-or-instructions), partial).
- **Project resource permissions vs identity permissions:** OpenAI's Terraform model/tool/retention controls define what a project can use; RBAC determines which users/groups can act on the organization or project ([Project controls](https://developers.openai.com/api/docs/guides/terraform/project-controls), partial; [Platform RBAC](https://developers.openai.com/api/docs/guides/rbac), partial).
- **Plan mode vs agent mode:** Copilot IDE plan mode drafts a read-only plan for approval; agent mode edits files and proposes/runs commands under host policy. Choose the surface based on whether implementation can begin before review ([Plan mode](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-plan-mode), partial; [Agent mode](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode), partial).
- **MCP connectivity vs authority:** OpenAI remote MCP and private tunneling describe how a tool endpoint is reached; approval policy still determines whether tool calls proceed. Treat outputs as untrusted data and enforce action limits outside the prompt ([MCP tools](https://developers.openai.com/api/docs/guides/tools-connectors-mcp), partial; [Prompt-injection design](https://openai.com/index/designing-agents-to-resist-prompt-injection), partial).
- **Terminal attachment vs hosted session:** Detaching the Anthropic CLI does not stop a Managed Agents server session; track the server-side session and pending approvals independently ([Connect to a session](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/sessions-connect), partial).
