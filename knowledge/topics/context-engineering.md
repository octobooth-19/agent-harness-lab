# Context engineering

**Snapshot and source retrieval date:** 2026-11-18; **last synthesis review:** 2026-11-18.
**Evidence status:** Original cross-provider guidance based on reviewed sources in the provider inventories. Context limits and mechanics are model/surface-specific.

## Practical guidance

1. **Optimize for useful signal, not maximum input.** Include the goal, constraints, relevant files, evidence, and success criteria. Retrieve additional context just in time instead of front-loading the entire repository or tool catalog.
2. **Keep context layered and navigable.** Use a concise entry-point instruction, then point to focused topic docs, task artifacts, and references. Load long procedures or examples only when they are relevant.
3. **Give tools bounded, descriptive interfaces.** Tool definitions and results consume context. Use specific schemas and names, return compact relevant results, and keep large intermediate data outside the model context when the runtime permits.
4. **Manage the context lifecycle.** Track what has been decided, what remains, evidence gathered, and the next action. Before compaction or handoff, write durable status to a task artifact; after compaction, verify that critical constraints and unresolved work survived.
5. **Separate context from durable state.** Conversation history is not a reliable database. Persist code changes, test results, decisions, and checkpoints in reviewable files or the host's documented session store.
6. **Handle truncation and recovery explicitly.** Preserve ordering and identifiers required by the provider's API, avoid replaying the same history through two state mechanisms, and verify resumed state instead of assuming a stream or tool call completed.
7. **Load tool definitions just in time when supported.** Large tool catalogs can consume context and increase selection ambiguity; defer infrequently used tools, but account for the extra lookup step and host/model-specific activation rules.
8. **Treat session events, artifacts, and traces as separate records.** Reconnect by retrieving durable state instead of assuming streams replay; store task outputs outside ephemeral execution environments and record enough identifiers to avoid repeating side effects.

## Provider-specific boundaries

- **OpenAI:** Codex instruction limits and discovery rules are product-specific; Responses API compaction and Agents API session/event state are separate mechanisms. Streams do not replay missed session events, so fetch session items and confirm turn state. Environment lifetimes are independent of sessions, and only selected OpenAI-hosted outputs are published as artifacts; self-hosted results remain the app's responsibility. A Cookbook example separates compaction within a long run from a human-reviewed memo that carries lessons to later runs. The Codex App Server JSON-RPC protocol is a separate integration path from external MCP-server connections; the docs mark it experimental and not production-supported. See [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Compaction](https://developers.openai.com/api/docs/guides/compaction), [Memory and compaction Cookbook](https://developers.openai.com/cookbook/examples/agents_sdk/building_reliable_agents_memory_compaction), [Codex MCP server removal](https://learn.chatgpt.com/docs/mcp-server), [Agents API events and items](https://developers.openai.com/api/docs/guides/agents-api/sessions/events), [Environment lifecycle](https://developers.openai.com/api/docs/guides/agents-api/environments/lifecycle), and [Files and artifacts](https://developers.openai.com/api/docs/guides/agents-api/environments/files).
- **Anthropic:** Context-window size does not establish context quality. For Messages API parallel tool calls, the client chooses safe concurrency and must return all results in the prescribed next message, keyed to their tool-use IDs. Tool definitions can be deferred, and the tool-context docs distinguish prompt caching, tool search, context editing and programmatic calling as different levers. The compaction docs describe on-demand behavior separately from threshold compaction; the new pages carry version/beta caveats. See [Context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows), [Context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents), [Manage tool context](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context), [Compaction](https://platform.claude.com/docs/en/build-with-claude/compaction), [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [Tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool), and [Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool).
- **GitHub Copilot:** Conversation context and Copilot Memory are separate; compaction can lose fine detail. Copilot CLI tool search can defer external tool definitions, but its activation threshold and model support are volatile and CLI-specific. The SDK's `clearContext` keeps session/event identity but clears model-facing history, is tool-handler-only, and is unavailable for remote sessions. CLI session history can also be stored locally and synced to the account by default; confirm sync policy before treating a session record as local-only. Remote GitHub MCP setup uses OAuth by default, with client-specific alternatives; enterprise policy and host support affect which server is available, so do not equate an index page with feature documentation. See [Context management](https://docs.github.com/en/copilot/concepts/prompting-and-context/context-management), [SDK context management](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/context-management), [Session data](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/chronicle), [GitHub MCP setup](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/customize-copilot/extend-copilot-with-tools-and-context/set-up-the-github-mcp-server) (partial), [GitHub MCP enterprise configuration](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/customize-copilot/extend-copilot-with-tools-and-context/enterprise-configuration) (partial), [Copilot Dreaming](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-dreaming), [Copilot Memory](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-memory), [Copilot SDK agent loop](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/agent-loop), and [tool search](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/tool-search).

## Uncertainty and conflicts

The cited docs cover distinct runtime state models; there is no provider-neutral context-window size, compaction format, replay contract, or memory retention policy. Product limits and model capabilities are volatile. Check the current doc for the exact surface in use, and keep an explicit source date when a limit or behavior is important to a design.

## Further guidance from the 2026-11-18 review batch

- Keep stable prompt prefixes stable when caching matters: exact-prefix reuse is sensitive to earlier prompt changes. Compaction may reduce reuse, so evaluate cache savings and context reduction as distinct goals ([OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), partial).
- Separate model context from execution state. The OpenAI Agents SDK sandbox guide assigns context, approvals, tracing, and run state to the harness, while files, commands, ports, and snapshots belong to the sandbox ([OpenAI Sandbox Agents](https://developers.openai.com/api/docs/guides/agents/sandboxes), partial). Anthropic likewise states that a Managed Agent session is not the model's context window ([Managed Agents research](https://www.anthropic.com/research/managed-agents), full).
- Delegate only when the task benefits from isolated context. Copilot IDE subagents return a result to the parent rather than sharing the entire conversation; their tool/model behavior depends on the IDE. State a bounded assignment and the required evidence in the handoff ([Copilot IDE subagents](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-subagents), partial).
- Load skills and tool definitions progressively, but inspect the host's discovery rules and limits. Claude Code documents on-demand skill loading and deferred MCP tool search, while Copilot's IDE subagent guide and OpenAI's skill formats describe different surfaces; do not assume one activation or context model ([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works), full; [OpenAI Build skills](https://developers.openai.com/plugins/build/skills), partial).
- Make the expected research artifact part of the task contract: Copilot CLI and app `/research` can produce a standalone cited Markdown report, while cloud-agent research remains inside the session. A link or chat result is not automatically a durable evidence record ([Copilot researching with agents](https://docs.github.com/en/copilot/concepts/agent-capabilities/choosing-and-delegating-agent-work/researching-with-agents), full).
- Treat observability payloads as context-sensitive data: the reviewed Copilot OpenTelemetry guide excludes prompts, responses, tool inputs/outputs and identity by default, with host/admin controls for expanded capture. Enable the minimum detail required for debugging and verify managed settings ([Copilot OpenTelemetry](https://docs.github.com/en/copilot/concepts/enterprise/opentelemetry), full).
- Distinguish context retrieval from data use and data location. Copilot repository indexing is separate from model training, but the reviewed VS Code guidance warns that indexing non-GitHub repositories can upload repository data to GitHub; obtain the appropriate authorization and verify host settings before enabling it ([Indexing repositories for GitHub Copilot](https://docs.github.com/en/copilot/concepts/prompting-and-context/repository-indexing), full).
- Keep model-facing context and execution-environment state in separate records. OpenAI's AWS guide distinguishes session deletion from stopping compute, and Databricks sandbox use is a separate application-managed beta integration; cleanup, credentials, files, and session history therefore need explicit lifecycle handling ([AWS Lambda MicroVMs](https://developers.openai.com/api/docs/guides/agents-api/environments/providers/aws), full; [Databricks Sandbox](https://developers.openai.com/api/docs/guides/agents-api/environments/providers/databricks), full).
- Treat provider-hosted async request storage as a separate context/data lifecycle. OpenAI Background mode requires retaining the response ID for retrieval and temporarily stores encrypted request data even when `store:false` or Zero Data Retention applies; design webhook/polling and deletion behavior around the documented live policy ([Background mode](https://developers.openai.com/api/docs/guides/background), partial).
- Use a shared context collection only with its source access model understood. Copilot Spaces can sync GitHub sources as they change, but a viewer still only sees accessible sources, and mixed private/organization content can affect cloud chat availability; it consumes model/token-based credits and is not a general memory contract ([Copilot Spaces](https://docs.github.com/en/copilot/concepts/prompting-and-context/spaces), full).
- Separate live previews from authoritative conversation history. Anthropic Managed Agents event deltas are best-effort, have a different wire format from Messages SSE, and must be reconciled with the buffered message event; open a session stream before sending input because it only receives later events ([Event stream](https://platform.claude.com/docs/en/managed-agents/events-and-streaming), partial; [Event deltas](https://platform.claude.com/docs/en/managed-agents/event-deltas), partial).
- Keep session configuration/version and session history explicit. Managed Agents can resolve a plain agent ID to its latest version, while a pinned version supports staged rollout; sessions are stateful and retain transcripts until deleted. Record which agent version and environment produced an artifact ([Start a session](https://platform.claude.com/docs/en/managed-agents/sessions), partial).
- For a voice or multi-surface agent, preserve verified application state and trace work across delegation. OpenAI's GPT-Live evaluation guide distinguishes the speaking frontend from the backend that reasons, invokes tools, and updates state; a spoken confirmation alone does not establish that the backend action succeeded ([GPT-Live evaluation guide](https://developers.openai.com/cookbook/examples/audio/voice_agent_evaluation), partial).
- For tools used in a real browser session, include the site/account context in the risk assessment. Copilot documents browser use as a preview and warns that it may act on already-authenticated sites; avoid high-impact actions without explicit confirmation ([Copilot browser use](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/browser-use), full).
- Model conversation continuity explicitly: distinguish the active prompt from replayable history, server-managed response IDs, and resumable interruption state. Preserve provider-required output metadata when replaying turns; for async tool calls, persist the `call_id` so the result can be attached to its originating request ([OpenAI results/state](https://developers.openai.com/api/docs/guides/agents/results), full; [conversation state](https://developers.openai.com/api/docs/guides/conversation-state), partial; [async tool calling](https://developers.openai.com/api/docs/guides/async-tool-calling), partial).
- Keep cache-sensitive prefixes stable, especially tool schemas and system instructions; evaluate cache invalidation separately from context compaction. Anthropic documents a tools → system → messages prefix order, while exact invalidation and TTL behavior is model/API-specific ([Anthropic tool caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching), full; [Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), partial).
- For retrieval, benchmark the retrieval pipeline on your own queries and corpus. Anthropic's contextual-retrieval experiment uses contextualized chunks plus retrieval/reranking; its reported gains and cost assumptions are study-specific, not a universal configuration target ([Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval), full).
- Choose tool execution ownership explicitly. The OpenAI Realtime API distinguishes application-executed function tools (useful when the app must own approvals or private access) from remote MCP tools called by the API, and supports response-scoped as well as session-scoped tool sets ([Realtime with tools](https://developers.openai.com/api/docs/guides/realtime-mcp), partial).
- Defer large tool catalogs only when the discovery cost is worthwhile. Claude Code SDK tool search reduces upfront definitions but adds a lookup round-trip and may fall back to loading tools up front on unsupported models or deployments; check the current host-specific settings ([Claude Code SDK tool search](https://code.claude.com/docs/en/agent-sdk/tool-search), partial).
- Treat streamed tool arguments as incomplete input until fully assembled and validated. Anthropic's fine-grained streaming guide warns that fragments may be invalid JSON or cut off at output limits, so guard parsing before executing a side effect ([Fine-grained tool streaming](https://platform.claude.com/docs/en/agents-and-tools/tool-use/fine-grained-tool-streaming), partial).
- Preserve the provider-required assistant payload when returning tool results. The reviewed Anthropic thinking/tool example requires echoing thinking blocks unmodified through the tool-use round trip; this is a Messages API contract, not a provider-neutral transcript rule ([Thinking in tool and multi-turn workflows](https://platform.claude.com/docs/en/build-with-claude/thinking-tool-workflows), partial).
- Defer a large tool catalog only when the saved prompt context justifies a discovery round trip. OpenAI's Responses API distinguishes hosted search over declared tools from client-side lookup; Copilot toolsets let callers narrow GitHub MCP exposure. Namespaces and lookup behavior are model/host-specific, and discovery does not grant permission ([OpenAI tool search](https://developers.openai.com/api/docs/guides/tools-tool-search), partial; [GitHub MCP toolsets](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/customize-copilot/extend-copilot-with-tools-and-context/configure-toolsets), full).
- Keep executable intermediate code within an explicit boundary. OpenAI programmatic tool calling runs in an isolated V8 runtime without general network/filesystem/process access or persistent JS state; prefer direct calls when a write needs approval. Treat this as a Responses API feature, not a general agent-runtime guarantee ([Programmatic Tool Calling](https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling), partial).
- Distinguish provider-hosted retrieval tools from sandbox egress policy. Anthropic Managed Agents domain lists apply to its hosted web tools, while self-hosted worker deployment and sandbox network access have separate controls; verify the exact tool, worker, and organization policy in the current docs ([Managed Agents web restrictions](https://platform.claude.com/docs/en/managed-agents/tools-web-restrictions), partial; [Deploy self-hosted workers](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes-workers), partial).
- Preserve a stable prompt prefix when cache reuse matters, and measure rather than infer the benefit. OpenAI's diagnostic comparison requires an exact prefix plus compatible model, service tier, and tool configuration; its response ID is diagnostic metadata, not conversation restoration. Anthropic separately documents cache invalidation from changing tool order/configuration ([OpenAI prompt-cache diagnostics](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics), partial; [Anthropic tool caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching), full).
- Distinguish retrieval/index state from the agent's model context and environment. OpenAI File Search is a hosted Responses tool over uploaded vector-store files; Copilot Fusion orchestrates selected models without having its own context window; Anthropic Managed Agents binds sessions to distinct sandbox environments. Verify each product's lifecycle, model limits, and citations rather than treating these as one shared memory layer ([OpenAI File Search](https://developers.openai.com/api/docs/guides/tools-file-search), partial; [Copilot Fusion](https://docs.github.com/en/copilot/concepts/models/copilot-fusion), partial; [Anthropic environments](https://platform.claude.com/docs/en/managed-agents/environments), partial).
- Treat model reasoning configuration as request/runtime metadata, not content that must appear in every context turn. OpenAI reasoning effort and Anthropic adaptive thinking/effort are model-dependent; Anthropic explicitly says thinking may be absent on a turn, while its per-message effort override is beta. Record the actual model and settings when reproducibility matters ([OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning), partial; [Anthropic thinking steering](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost), partial; [Per-message effort](https://platform.claude.com/docs/en/build-with-claude/effort-per-message), partial).
- Keep conversation state, sandbox files, and provider-session records separate. OpenAI's self-hosted environment examples require application-owned session-to-sandbox mapping and separate cleanup; Copilot local sandbox settings do not apply to cloud or remote-host sessions; Anthropic Managed Agents stores session history separately from its sandbox ([OpenAI E2B environment](https://developers.openai.com/api/docs/guides/agents-api/environments/providers/e2b), full; [Copilot local sandbox settings](https://docs.github.com/en/copilot/how-tos/cloud-and-local-sandboxes/configuring-local-sandbox-settings), partial; [Anthropic environment selection](https://platform.claude.com/docs/en/managed-agents/choosing-an-environment), partial).
- Keep the trusted harness and execution workspace distinct when untrusted code runs. The OpenAI Agents SDK cookbook places policy, credentials, approvals, and audit in the host, stages only task-scoped files into a sandbox, and returns a patch/report; treat the sample's Docker/provider setup as an implementation example rather than a universal SDK contract ([Sandboxed code migration](https://developers.openai.com/cookbook/examples/agents_sdk/sandboxed-code-migration/sandboxed_code_migration_agent), partial).
- A self-hosted server does not imply local model processing or zero-retention data. Anthropic's self-hosted Managed Agents server sends conversation and tool data to its configured inference provider; separately audit worker egress, session database, backups, telemetry, memory stores, and persistent workspace volumes ([Data and access](https://platform.claude.com/docs/en/managed-agents/self-hosted-data-and-access), partial).
- Delegate only independently bounded work when separate context helps; OpenAI's beta multi-agent flow gives subagents their own focused context and has a root agent synthesize results, while shared mutable state or a sequential dependency chain favors one agent. Model support and item schemas are beta-specific ([Responses API multi-agent](https://developers.openai.com/api/docs/guides/responses-multi-agent), partial).
- Keep task workspace, reusable environment setup, and persistent memory distinct. Codex Cloud gives each task its own workspace, while an environment supplies setup rather than shared task state; inspect the task diff before exporting or applying its work ([Codex Cloud](https://learn.chatgpt.com/docs/cloud), full).
- Treat retrieved passages as selected evidence, not automatically trusted instructions or durable memory. OpenAI's partial Retrieval guide describes vector-store semantic search; preserve source/provenance and validate the retrieved content before using it to guide actions ([Retrieval](https://developers.openai.com/api/docs/guides/retrieval), partial).
- Map the Copilot client's session storage and sync behavior into the data-flow diagram before using it for sensitive work. The reviewed session-data page is partial, so check the exact client and policy rather than assuming local execution means local-only records ([Session data](https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/session-data), partial).
- Monitor Managed Agents using both events and current session/run state: webhook delivery may be missed, idle may mean input is required, and session history can outlive sandbox artifacts or require separate cleanup for memory/vault data ([Monitoring](https://platform.claude.com/docs/en/managed-agents/secure-deployment-monitoring), partial; [Managed Agents reference](https://platform.claude.com/docs/en/managed-agents/reference), partial).
- For GPT-Live client delegation, use transcript events and application state to construct backend context; delegation metadata alone does not contain task text. Choose explicitly whether the backend receives conversation history, selected memory, and application records, and validate its result before relaying it ([Delegation and tools](https://developers.openai.com/api/docs/guides/live-delegation), partial).
- For GPT-6.2 Responses conversations, avoid rewriting earlier input prefixes when preserving reasoning items or prompt-cache reuse matters; put reusable developer guidance at the beginning of `input` and verify the current model's request semantics ([Using GPT-6.2](https://developers.openai.com/api/docs/guides/latest-model/gpt-6.2-astra), partial).
- Separate self-hosted Managed Agents configuration, secrets, inference provider, database, and per-session sandbox boundaries. Self-hosting changes the operator's responsibilities but does not, by itself, specify where inference or every log/data copy resides ([Self-hosted configuration](https://platform.claude.com/docs/en/managed-agents/self-hosted/configuration-reference), partial; [Inference provider](https://platform.claude.com/docs/en/managed-agents/self-hosted/inference-provider), partial).
- For Anthropic models with preserved thinking, replay assistant content blocks exactly and append changed instructions/tools rather than rewriting the earlier conversation prefix. Treat this as model/API-specific serialization behavior, separate from the application's durable memory store ([Change tools or instructions](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/change-tools-or-instructions), partial).
- For browser/computer agents, the application supplies the driver and controls the actual browser/desktop environment; configure and test URL checks and approval callbacks before dispatching actions ([Browser and computer use SDK](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-sdk), partial).
- Keep enterprise governance state reviewable. Copilot's `.github-private` repo supports pull-request and CODEOWNERS review for shared agent/plugin settings, while cloud-session policy and SSO scope determine access to related session data ([`.github-private` governance](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/manage-agents/create-github-private-repo), partial; [Copilot in the cloud](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/manage-agents/manage-copilot-in-the-cloud), partial).
- For Realtime API integrations, model the session/conversation as state updated by client and server events; keep the event lifecycle distinct from GPT-Live's backend delegation and application-managed state ([Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations), partial).
- For MCP-based integrations, distinguish the data/context path from action authority: choose remote vs private tunnel based on network placement, constrain tool output, and configure approval for sensitive calls ([OpenAI MCP server tools](https://developers.openai.com/api/docs/guides/tools-connectors-mcp), partial; [Copilot GitHub MCP server](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/copilot-for-common-tasks/use-the-github-mcp-server), partial).
- Give an agent only the evidence needed for its stage, and keep the app's authorization, identity, and query limits outside its context. The OpenAI data-agent example partitions schema lookup, contextual retrieval, bounded read-only queries, and memory writes into separate tools ([Data analyst with the Agents API](https://developers.openai.com/cookbook/examples/agents_api/apps/data_analyst/readme), partial).
- For SDK subagents, use separate context for independent subtasks and return concise findings rather than copying all intermediate tool history into the parent; restrict each subagent's tools to its actual need ([Anthropic subagents](https://code.claude.com/docs/en/agent-sdk/subagents), partial).
- Session persistence does not itself solve multi-tenant isolation: assign stable project/session keys and enforce store authorization, encryption, and retention at the backend ([Anthropic SessionStore](https://code.claude.com/docs/en/agent-sdk/session-storage), partial).
- Keep session continuity aligned with the user's thread and workspace boundary; use a separate isolated workspace per session where the execution model requires it, and keep credentials in the trusted application ([OpenAI Slack bot example](https://developers.openai.com/cookbook/examples/agents_api/apps/slack_bot/readme), partial).
- For SDK automation, provide an explicit model and only the tools/URLs the task needs; prefer guarded workflow integrations over broad direct CLI permissions ([Copilot CLI programmatic guidance](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically), partial; [GitHub Actions guidance](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/automate-with-actions), partial).
- For work tracking at scale, bind tasks to isolated agent workspaces and make the board/session state explicit; keep human review attached to the deliverable rather than supervising only by terminal session ([OpenAI Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/), partial; [Copilot session management](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents), partial).
- Separate documentation retrieval from operational tools. OpenAI Docs MCP is read-only and can add current API documentation as context; App/plugin MCP workflows have separate review and access contracts ([Docs MCP](https://developers.openai.com/learn/docs-mcp), partial; [Remote MCP review](https://developers.openai.com/plugins/deploy/app-review), partial).
- Before connecting an app that can receive organizational data, make the connection and relevant context sharing visible to the user and constrain access through the app/host permissions ([ChatGPT Apps launch](https://openai.com/index/introducing-apps-in-chatgpt/), partial).
- When using the Anthropic Agent SDK, explicitly choose `settingSources` and audit filesystem/host inputs that remain active regardless: managed policy, global config, auto memory, and eligible connectors can still contribute context. For multi-tenant processes, isolate filesystems and disable automatic memory/connectors as required; `settingSources: []` alone is not isolation ([Claude Code features in the SDK](https://code.claude.com/docs/en/agent-sdk/claude-code-features), full).
- Keep task/session history, working files, and loaded capabilities separate. Anthropic SDK skills are discovered from enabled filesystem sources and loaded on demand, while Copilot SDK per-agent skills are injected in full at startup and are not inherited automatically by subagents ([Anthropic SDK skills](https://code.claude.com/docs/en/agent-sdk/skills), partial; [Copilot SDK custom agents](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/custom-agents), partial).
- Use an explicit output schema or bounded intermediate processing only when it fits the work: GPT-5.6 guidance reserves Programmatic Tool Calling for predictable data processing, and keeps direct calls for judgment-dependent steps, approvals, or final evidence/citation preservation ([Using GPT-5.6](https://developers.openai.com/api/docs/guides/latest-model/gpt-5.6), full).
